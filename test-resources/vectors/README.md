# Golden vectors

Format version `firmament-0`. These files are the final authority over the
spec text in [docs/spec/](../../docs/spec/). They are generated by
[reference/gen_vectors.py](../../reference/gen_vectors.py) and must not be
edited by hand.

| File | Covers |
| --- | --- |
| `encoding.edn` | Canonical EDN: valid values with bytes and hashes, NFC normalization, and inputs a decoder must reject |
| `blobs.edn` | Blob hashes |
| `gear.edn` | The chunker's gear table |
| `chunking.edn` | Blob-or-chunked choice, cut points and file root hashes |
| `index.edn` | Chunk index building: node boundaries, the 4096-entry cap, multiple levels |

## Reading the files

Each file is one EDN map with a `:format` key and one or more vectors of
cases. They are ordinary EDN, not canonical EDN, and read with
`clojure.edn/read-string` given readers for two tags:

- `#h "sha256:…"` — a link.
- `#b64 "…"` — a byte string (standard base64 with padding).

The files are pure ASCII. Non-ASCII characters in strings are written as
`\uXXXX` escapes of their UTF-16 code units, so a value means the same thing
in any EDN reader. Byte sequences, such as canonical encodings and invalid
inputs, are lowercase hex strings under `:hex`. Hashes are `"sha256:<hex>"`
strings. Every case has a `:name`, which is descriptive only.

## What an implementation must check

**encoding.edn**

- `:valid` — `encode(:value)` equals the bytes of `:hex`; decoding those
  bytes gives `:value`; `SHA-256("edn\n" + bytes)` is `:hash`.
- `:normalize` — `:value` contains strings that are not in NFC.
  `encode(:value)` equals `:hex` (encoders normalize). Decoding gives the
  normalized value, not `:value`.
- `:invalid` — decoding the bytes of `:hex` fails.

**blobs.edn** — `SHA-256("blob\n" + bytes)` is `:hash`.

**gear.edn** — `:gear` is 256 strings of 16 hex digits; entry `i` is
`GEAR[i]`.

**chunking.edn** — for the bytes described by `:data`: `:chunked` says
whether the file is a single blob or a chunked file, `:cuts` lists each
chunk's end offset (chunked files only), and `:root` is the file's hash.

**index.edn** — build the index over the level-0 entries described by
`:entries`. `:levels` gives, for each level from 0, the number of entries in
each node; `:root` is the hash of the root `:chunked` node.

## Generated data

Inputs that would be too big to store are described by a spec under
`:data`:

| Spec | Bytes |
| --- | --- |
| `{:gen :zeros :length n}` | `n` zero bytes |
| `{:gen :sha256-ctr :seed s :offset o :length n}` | bytes `[o, o + n)` of the stream for `s` |
| `{:gen :concat :parts [spec …]}` | the parts, concatenated |

The **sha256-ctr stream** for seed `s` is the concatenation, for
`i = 0, 1, 2, …`, of `SHA-256(utf8(s) ‖ uint64be(i))`, where `uint64be(i)` is
`i` as 8 big-endian bytes.

In `index.edn`, `:entries {:seed s :count n}` means `n` entries where entry
`i` links to `"sha256:" + hex(SHA-256(utf8(s) ‖ uint64be(i)))` (block `i` of
the same stream) and has `:size` `65536 + i`. These links are arbitrary
hashes, not real chunks; only their digests matter for boundaries.

## Changing the vectors

Until `firmament-0` is frozen, change the spec, the reference and the
vectors together, then run:

```
python3 reference/gen_vectors.py          # rewrite the files
python3 reference/gen_vectors.py --check  # verify they are current
```

After the freeze, existing vectors never change; only new cases may be added.
